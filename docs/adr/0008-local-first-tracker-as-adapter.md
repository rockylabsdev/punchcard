# Local first: Punchcard is a time tracker, and Jira is one optional tracker behind it

Punchcard's identity is the timing: presence, focus, held timers, recovery, and one timer for one user's attention. Sending the time somewhere is a feature on top. Until now the code has had this shape but the words have not. `core` and `store` import nothing from `jira`, the whole remote surface is a three-method interface, and tests already run against a fake, yet an unconfigured Jira is treated as being offline, every stopped entry is **owed**, and the TUI, the band and the exit codes apologise until credentials appear. We decide that **a Punchcard with no remote is complete, not degraded**. The remote is a **tracker**, an adapter chosen in config, of which Jira is the first and, for now, only implementation. The seam is what it is today (`Verify` a key for its summary, `Submit` a worklog for a remote id, `Test` the connection) plus one more answer: what a key looks like here. The core, the store, the stop semantics and the plugin's switching do not change. **This lands before the first release**: nothing is tagged, no user has a state file, so `local` is in `state.json` schema 1 from the start and no migration code ever exists.

**A worklog is final at stop, with or without a tracker.** Stop stays the one action that produces a worklog (truncated to the minute, duration editable, one per entry). With no tracker the worklog's state is **local**: final, nowhere to send, never owed. With a tracker it is pending until the tracker takes it, as today. The state is decided at stop time by the tracker configured then. Removing the tracker in `setup` offers, once, to mark every pending and failed worklog local (duration and comment kept, the failure message dropped); declined, they stay owed until sent, and no CLI flag forgives debt. `rm` refusing to throw away unlogged time counts a local worklog as logged.

**A ticket is whatever the tracker says it is.** Jira's key grammar (`ABC-123`, upper-cased on entry) becomes Jira's rule, not the core's. Without a tracker a key is a **slug** (`[A-Za-z0-9][A-Za-z0-9._-]*`), case-sensitive and stored as typed; Jira's grammar is a subset, so a user who later adds Jira keeps their keys. The summary is what the user typed when adding the ticket, and **unverified** does not apply: it is set only by an add that asked a tracker and got no answer.

**A session's key is resolved once, in the binary.** Two sources, in order: a **`.punchcard` file**, then the git branch. The file holds one key on its first line (`#` lines ignored) and is found at the nearest ancestor of the session's directory, stopping at the repository root; a first line that is not a valid key counts as no file, with a notice. The branch rule stays "a key of the `ABC-123` shape anywhere in the name" (it is Linear's shape too). That one answer feeds `touch --cwd`, the band and `/punch start` with no key; `status --json --cwd DIR` reports it as `here: {key, source}` so **the plugin asks the binary and never carries a regex of its own**. Focus itself is unchanged: it switches an un-held running timer, adds the ticket if it is not on the list, never starts a timer from idle and never moves a held one.

**A blank machine times work with no ceremony.** `punchcard start payroll` works with no config file; no file means no tracker. The TUI's empty-list screen says "no tracker · S to set one up" and nothing else nags. `setup` is for the two optional things, a tracker and the plugin; its first question is which tracker, if any, and the Jira steps follow only for Jira. Config gains `tracker` (`none` or `jira`); a config with `siteUrl` and `email` and no `tracker` reads as `jira`.

**Export is the tracker for everyone without one.** `punchcard log` lists worklogs over a range as `--json`, `--csv` or `--md`. One row per worklog; open entries have no row. `--csv` has a header and the columns `date, started, key, summary, minutes, comment, state, remote_id, entry_id, recovered`: `date` is the worklog's day as CONTEXT.md defines it, `minutes` the truncated duration as an integer, `state` one of `local|pending|synced|failed`. `--json` carries the same rows and the open entry as a separate field. `--md` is a heading per day with the day's total, a `key | summary | time | comment` table under each, a grand total at the end, no state column (`· pending` and `· failed` mark the exceptions) and a footer line for a running or paused entry so the total is never silently short. Ranges are local: `--week` (the default) is Monday through today, `--month` the calendar month through today, `--from`/`--to` inclusive dates. It is a read: it exits 0 (empty rows included), never calls a tracker, and is never presence. CSV is what every tracker and spreadsheet imports, so it is the one integration that covers Clockify, Toggl, Harvest, Tempo and a timesheet in an email at no cost per target. **Reporting stays flat**: one row per worklog, grouped by day. There are no projects, clients, tags or rates, and no second grouping. Those are Clockify's identity, not Punchcard's; Punchcard answers how long the user was actually on a ticket, and that is all it answers.

## Considered Options

- **Keep Jira built in and add a "no sync" switch.** Rejected: the switch would still leave every other surface (the strip, the band, exit 3, the wizard) assuming a remote exists and nagging for it. Changing the default is the whole point.
- **Ship v0.1.0 Jira-only first, local-first as v0.2.0 with a schema bump.** Rejected: the bump is cheap but permanent, and the "refuse a newer file" rule means nobody could downgrade past it. With no users, folding it in costs only the delay.
- **A tracker as a plugin or subprocess.** Rejected: there is one implementation, Go interfaces are enough, and a second process contradicts ADR 0001's "no daemon". A tracker is a Go package behind the interface, selected by `tracker` in config.
- **Rename `Worklog` to something tracker-neutral.** Rejected: "work log" is a plain phrase, `TimeEntry` is already taken for the measured period, and a rename would touch every type, file, doc and CLI field for no new meaning. The name stays; it gains a state.
- **Loosen the key grammar for everyone.** Rejected: with Jira the strict grammar refuses typos before they become unverified tickets, which is worth keeping. The grammar is the tracker's.
- **The whole branch name as the key, for the trackerless.** Rejected: `main` and `fix-typo` become tickets, and the user can only stop it by renaming branches. A repository file is explicit, names what the repository is for, and works for a Jira user whose branch carries no key too.
- **A `.punchcard` with room for more fields (`key=`, JSON).** Rejected: one key is the whole decision, and a format with room for fields invites fields. If one is ever needed, the first line stays the key.
- **Case-insensitive keys.** Rejected: folding every comparison touches `core` for a problem only a typo creates, and the TUI shows the typo at once.
- **A `mark-local` CLI flag for pending worklogs.** Rejected: a flag that forgives debt outside `setup` is a footgun for agents. The offer lives where the user is clearly saying they are done with the tracker.
- **A stored "first run" flag for the no-tracker note.** Rejected: a flag for a one-line hint. The empty-list screen is where a first run lands and the note leaves with the first ticket.
- **A bundled report UI (HTML timesheet) in the first cut.** Deferred: Markdown probably covers it; an HTML renderer is a read over the same rows and can come later without a decision.
- **Local mode skips the agent stop gate.** Rejected: `stop --yes` from an agent still finalises a duration on the user's behalf, and the user's hours are the thing being protected (ADR 0005). The dialog's words change ("Log it" without a tracker, "Send to Jira" with one); the gate does not.
- **An archive command in this release.** Deferred: `touch` reading the whole file is the only cost, a year of daily entries is a few hundred kilobytes of JSON, and an archive adds a second file the store must lock and every read must merge. The trigger for revisiting is `log --from` wanting history that `state.json` no longer holds.

## Consequences

- **The CLI contract stays `v: 1`** (additive, ADR 0004): `worklog.state` gains `local`; `status --json` gains `tracker` (`none` or `jira`) and, with `--cwd`, `here`; `log` is a new read. The exit codes keep their numbers but narrow their reach: 3 (`not_configured`) and 8 (`auth_failed`) fire only when a tracker is configured and needed; 5 (`ticket_not_found`) only with a tracker that verifies; 7 (`sync_pending`) never without a tracker. The skill's exit-code glossary and its key-finding instruction are reworded: the agent reads `here` rather than regexing a branch.
- **The band is quiet without a tracker.** `configured: false` stops being a warning; the band shows the timer and nothing else. Jira's auth and Keychain conditions appear only when `tracker` is `jira`. "This branch is KEY" becomes wording that does not name the branch, since the key may be the file's.
- **`[3] Jira` in the TUI becomes the day's log**: logged today, and with a tracker, what is owed.
- **The `jira` package leaves the callers' vocabulary.** `worklog`, `cli`, `tui` and `setup` match a tracker-neutral error set (not found, unauthorized, unreachable, refused with a status) rather than `jira.Err*`, and `tui/pane.go` stops parsing the text "Jira answered NNN". `jira` keeps its wire types and ADF comment; "issue" stays confined there as before.
- **Local mode has no forgetting.** With a tracker, synced history has a home elsewhere; without one, `state.json` is the only record and grows for as long as the user works. Deferred, with the trigger named above.
- **CONTEXT.md changes with this decision**: the opening sentence (a time tracker; a tracker is optional), **Ticket** (the tracker's word, not Jira's), **Unverified** (only with a tracker that verifies), **Worklog** (gains local; "what the tracker is told, or the final record when there is none"), **Stopped** ("a worklog is produced", not "for Jira"), **Focus** (a `.punchcard` file or a key in the branch name), and a new term **Tracker**: the optional remote a worklog is sent to, of which Jira is one. The glossary stays free of the config field and the package names.

## Amendment (2026-10-12, #48): a lowercase branch key counts when its project is known

The branch rule widens to a key of any case: `ka-6629-ship-it` and `feature/ka-123-x` name a ticket as `KA-6629-ship-it` does. A token that is not all capitals counts **only when its project prefix (the part before the last `-digits`) matches, ignoring case, the prefix of a ticket already on the list**. It is then spelled with that ticket's prefix, so a branch never adds a second spelling of a project: with Jira or a tracked `KA-1`, `ka-6629` is `KA-6629`; with no tracker and a tracked `ka-1`, it stays `ka-6629`. An all-capitals token counts as before, known project or not. The first token, left to right, that counts is the key, and it still goes through the grammar's `Normalize` and `Valid`.

The reason is false positives. Lowercase branch names are full of dash-number words (`release-2026`, `fix-2`, `hotfix-12`). With Jira a matched key is upper-cased and, on focus, added to the list unverified, so a loose match would move the timer onto a ticket that does not exist. Gating on a known project cannot invent tickets. Its cost is the first ticket of a new project on a lowercase branch: it is not picked up until one ticket of that project is on the list (start it once by hand, or add a `.punchcard`). A session's key therefore depends on the ticket list as well as the directory; both are read at resolution time and nothing about it is stored.

- **Considered: case-insensitive anywhere.** Rejected for now: every dash-number word becomes a ticket. Revisit if the known-project gate proves cumbersome.
- **Considered: lowercase only at the start of the branch or of a `/` segment.** Rejected: `release-2026` and `fix-2` start there too.
- **Considered: a configured list of project keys.** Rejected: a setup question and a config field to answer what the ticket list already knows.
