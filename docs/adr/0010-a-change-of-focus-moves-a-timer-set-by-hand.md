# A change of focus moves a timer set by hand

Until now focus from a prompt never moved a **held** timer, one the user started by hand (ADRs 0001, 0005, 0008). In daily use across parallel Claude Code sessions that rule fought the app's strongest signal: moving between sessions on different tickets says what the user is working on, yet a timer started by hand ignored it, so the user switched by hand every time. ADR 0009 changed the cost of lifting the rule. Focus is edge-triggered, so letting it override a start by hand moves the timer when the user **moves between sessions**, not on every prompt. We decide that **a change of focus moves the running timer whoever set it**, by hand, by prompt or by agent. This is the default and the only behaviour; there is no setting. Focus still never starts a timer when nothing runs, and a paused timer counts as nothing running.

The whole policy is one sentence: **the timer runs on the ticket of the session the user last prompted in; if they move it elsewhere themselves, by hand or by asking the agent, it stays there until they prompt in a session on a different ticket; nothing starts a timer except the user.**

**Held is renamed "by hand" and narrowed to what it still means.** A timer the user set by hand is one an agent cannot move (`start`, `pause`, `resume` from origin `agent` still refuse it); the user's own focus can. ADR 0005 is otherwise unchanged. The old word said "pinned against everything", which was no longer true, and the phrase the docs kept reaching for to explain it was the better name. It is already the project's idiom (**Origin** has `hand`), so the glossary loses a term: **Held** folds into **Origin** in `CONTEXT.md`.

A start by hand still does not write the last focus (ADR 0009). So a timer started by hand stays put through further prompts in the session the user was already in, and moves at their first prompt in a session on another ticket. That is "protected until the next change of focus", and it falls out of the existing rule for free.

## Considered Options

- **An opt-in "follow me" mode, chosen in `setup`.** Rejected. Punchcard is single-user and nothing is released, so a default change costs no migration. A mode costs a config field, a `setup` question, a way to show the mode in the band and `status`, and twice the behaviour to test and document, for a flag only its author would flip. If daily use proves the old rule right, an opt-out is easy to add; removing a mode people rely on is not.
- **Also starting a timer from idle on a prompt.** Rejected for now. A prompt in a keyed session may be a question, not work, and the band already nags (`KEY not running · /punch start`). This is the one piece of friction left, and the one the user will meet daily. **Open question:** if the morning `/punch start` turns out to be the real cost, revisit *this*, not the by-hand rule.
- **Deleting held entirely, so an agent may move any timer.** Rejected. An agent's autonomous start would move the timer with no input from the user, and the timer measures the user's attention, not an agent's work (`CONTEXT.md`, Running).
- **Keeping the name "held".** Rejected. It overstates the guard, and it sat exactly where the user reads it every day, in the band. "By hand" names the cause, which is the one thing that is unambiguously true; the effect follows.
- **Protecting a start by hand until the next change of focus, as a separate rule.** Not needed: ADR 0009 already gives it, because a start by hand does not write the last focus.

## Consequences

- **The rename reaches every surface.** The entry's `held` field becomes `byHand` in `state.json` and the JSON envelope; the `held` event becomes `byHand`; the exit 4 failure code `held` becomes `by_hand`; the band, the CLI and the TUI show `by hand`; the toast reads "`KEY` set by hand: agents can't move it". No migration: nothing is tagged and no state file exists.
- **The band's "elsewhere" state becomes a meaningful signal.** `timer on X · this branch is Y` is now reachable only by an override the user made inside a session, or from a session with no ticket, instead of being the constant sight it was while a held timer ignored focus.
- **An agent starts a timer only when the user asks.** The model holds only because of this convention, so the skill states it. An agent's autonomous start would not be pulled back by focus (ADR 0009) and would measure the agent's work. This is where the model leaks as agents grow more autonomous; watch it.
- **The guide changes.** The hedge "today a prompt only moves a timer that already runs" goes, replaced by the one-sentence policy; the band table describes an un-held timer as one an agent may move too. `docs/spec.md` and `docs/spec-local-first.md` stay as dated records, as they did for ADR 0009.
- **Observability is the next investment, after v0.1.0.** Trust in an automatic timer comes from being able to audit it. The user should be able to see *why* the timer is where it is and what moved it during the day: a record of focus moves ("moved by your prompt in `~/work/pun-1`", "started by the agent in session X", "set by hand") readable from `log` or the TUI. Nothing stores that today; a move leaves only a paused and a started event in one command's envelope. This is deliberately out of scope for #49 and recorded here so it is not lost: it is what makes "run five agents, bill your real hours on the right tickets, never touch the clock" a claim the user can verify rather than take on faith.
